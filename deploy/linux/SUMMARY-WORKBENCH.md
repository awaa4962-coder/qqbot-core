# 日报工作台

适用版本：`1.4.6-summary-workbench` 及之后的 Linux 分支。Windows 安装继续冻结。

## 使用

1. 打开服务器网页版 `/console/`，进入左侧「日报」。访问仍需要已有的管理令牌和 SSH 隧道。
2. 选择日报白名单内的群和日期，默认昨天。查看当前采集量及覆盖提示，点击「生成草稿」。这会调用模型，但不会发到 QQ。
3. 生成后可查看正文和脱敏证据。修改全文并「保存为新版本」不会覆盖旧稿；当前日期和群最多保存十个版本，存在未完成发送时优先保留该次发送的原稿，其余保留最新版本。
4. 「对照版本」展示旧稿。「重写该讨论」只替换所选结构化讨论，其他讨论不变，并清掉可能过时的总括句。全文手工编辑的版本不再伪装成模型结构化稿，可选择此前结构化版本进行单讨论重写。
5. 确认群、日期和正文后单独点击「发送到目标群」。定时、启动补发和手动发送共享账本，同一群同一天已发送后不重复发。

明确失败且已有部分段落成功时，可以继续同版本剩余分段。网络断开等导致结果未知时，必须先去群里核对对应分段，再选择已送达或未送出；系统不会猜测，也不会整篇重发。分段全部有回执但完成登记中断时，可以核实后确认完成。

群内 `@机器人 日报预览` 默认当前群；跨群预览只能通过管理员私聊或受保护的控制台。`日报发送` 仍受日报群白名单约束。

## 数据范围

- 新采集只在升级后开始，不承诺恢复过去未采到的消息。旧滚动记录仍会合并使用并提示可能缺段。
- 每群每天最多 10000 条 / 6 MiB，单条正文最多约 1800 字符，保留头尾并标记截短；证据进入模型前再按讨论分配预算。
- 按日文件和草稿保留今天及此前六个自然日，由启动及每小时维护清理。只保存文本、身份和引用所需字段及媒体数量，不保留图片 URL。
- 统计表示“已采集记录”，首末时间不被当作全天完整的证明。
- 程序检查讨论和证据编号的合法性，不保证模型对事实、反讽或因果的理解完全正确；应使用证据对照和回放检验质量。
- 「忘记我」会清理新增按日记录及包含该用户材料的草稿，并阻止清理前启动的生成结果重新写回。已经发到群里的消息不会自动撤回。

## 模块

- `group-summary/journal.mjs`：按日采集、合并、保留期与清理。
- `group-summary/analysis.mjs`：讨论分组、证据预算、结构校验与排版。
- `group-summary/reports.mjs`：草稿版本与私有证据快照。
- `group-summary/publisher.mjs`、`guard.mjs`：统一发布、回执、续发和未知状态核实。
- `admin-api/summary-manager.mjs`：工作台任务与管理操作。
- `Web/summaries.js`、`summaries.css`：Linux 浏览器工作台。

更新备份需包含 `state/qqfriend/config`、`state/qqfriend/data` 和 `state/qqfriend/logs/summary-state`。保留旧发送标记，禁止通过清空账本处理重复发送。
