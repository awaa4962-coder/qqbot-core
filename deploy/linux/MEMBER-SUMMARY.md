# 成员聊天总结

Linux `1.4.8-member-summary` 起可用。普通群成员不需要管理员权限，但必须在已启用群内 @机器人；私聊不读取任何群记录。

## 命令

| 用法 | 含义 |
| --- | --- |
| `@夜星 总结我` | 自己最近两小时说了什么 |
| `@夜星 总结 @某人 昨天` | 指定成员昨天的发言 |
| `@夜星 总结 @甲 @乙 最近1小时` | 自然串讲这几人参与的事情 |
| `@夜星 分别总结 @甲 @乙 今天` | 每个人分别写一小段 |
| `@夜星 总结 @某人 最近7天` | 今天及此前六天内的已采集记录 |
| `@夜星 总结帮助` | 查看用法 |

名字前的 @ 要使用 QQ 的选人功能，不是手打同名字符串。机器人自身不算目标，最多五人；`@全体成员` 不支持。还可以使用 `最近30分钟` 或 `YYYY-MM-DD` 日期。超出最近七个自然日的请求会提示缩小范围，不静默扩大查询。

## 内容与模型

原话先按当前群、指定身份和时间筛选，再补少量引用链及必要邻近背景。程序不先生成主题、结论或人物评价，而是将带日期和人物标签的原话直接交给 API，用提示词要求自然、简明地讲清事情。多人没在互相聊天时，不强凑争论或共识。

输入最多按每人最近六十条轮流取样，目标文字预算约 9500 字符、背景约 2200 字符，单条最多 600 字符并保留头尾。实际进入模型的条数、采样和可能缺失会附在正文后。各目标预算轮流分配，不同人的同一句话不会直接合并成一个人的说法。

新的 `conversation_summary` 插槽在 API 页显示为「成员聊天总结」。没有单独配置时，首次读取旧 API 配置会继承其日报插槽；前端保存后可以独立调整。主模型失败、空正文、仅有推理或被截断时尝试备用模型，不增加额外润色轮次。

## 配置与边界

- 控制台「配置 → 聊天总结群」独立控制可用群。没有配置时继承功能群；显式清空列表关闭该功能。保存配置后按现有方式重启 Bridge 生效。
- 环境变量为 `QQBOT_CONVERSATION_SUMMARY_GROUPS`，旁文件为 `.env_conversation_summary_groups`，环境变量优先。
- 同群一次只运行一个任务，默认一分钟冷却；总共最多两个成员总结任务并行。第一条回复表示正在处理，之后才是总结结果。
- 控制台「诊断 → 成员总结任务」只显示群、时间、人数、进度和模型，不展示聊天原文或结果正文。任务失败不自动重做，发送未确认不自动重发。
- 不改每日群报的推送群，不新增历史采集。按日记录只存在于原有日报采集群，其他群最多使用仍保留的滚动消息；无法恢复未采集、已过期或被清理的记录。
- 不读人物画像、关系分数或其他群与私聊，不把总结写回画像。纯图片、文件内容不在本轮范围，不新增识图调用。
- 「忘记我」的清理代次会在读数据、调用备用模型及发送前检查，旧材料不能在清理后继续进入备用调用或外发；已发送到群的消息不会自动撤回。

模块路径：`bridge/features/conversation-summary/`，分别负责命令、选记录、提示词/API、任务和发送。复用现有命令分发、JSON 任务元数据、模型路由、脱敏与发送工具，不使用日报同日去重账本。
