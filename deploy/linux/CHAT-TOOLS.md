## 已有边界

Linux `1.4.21-scoped-tools` 为已开放聊天的用户提供按需读取，不增加后台意图模型或无限工具循环。

`1.4.39-stable-cache` 候选继续使用原四次工具/90秒会话边界，不新增长期搜索库。缓存只在校验、输入许可、来源守卫和打包限额通过后保存脱离原对象的原始资料；失败、非法或过大结果不缓存，状态查询仍每次读取。参数序列化稳定，跨用户、群、会话及新的修订不能复用；已停止的会话不能通过把权限改回来复活旧缓存。模型/模板切换不把原始证据冒充旧模型答案，本轮真实状态按当前模型重新读取。

公开搜索保持既有1600字符摘录上界，长结果带`truncated:true`，不因长度直接禁用有效搜索；完整打包若仍超过原2000字符/累计6000预算则明确不可用。调用者只能看到本轮授权的摘录，不把未提供的尾部当作已读取。读取配置的比较仅保留散列，不额外长期保留凭据副本。

## 预算

- 主/备共享最多 4 个模型回合，每插槽最多 3 回合；主插槽最多用 3 个，给备用保留一个。最后可用回合不再声明工具。
- 模型传输最多 8 次尝试，保留原有最多一次暂态重试；每次请求的完成额度不超过原任务上限或 1536 token。累计请求额度上限不等于实际费用，供应商报告的 token 仍走原用量系统。
- 工具处理最多 4 次，整个聊天工具流程期限 90 秒。单请求消息与工具声明序列化不超过 24000 字符，包含自身信息和内部原生续接；过大时不截断签名或拆坏调用配对。
- 单工具输出不超过 2000 字符，累计 6000 字符；记忆处理器先按完整记录做更小的打包。相同查询只在本轮复用，权限/隐私变化后不能复用；状态查询每次重新读现有快照。
- 累计输出预算包含拒绝回执，并为剩余调用预留空间；模型响应按流接收最多 256 KiB，超限取消读取且不重试。最终正文最多 6000 字符，超限视为失败并保留原备用路径，不向 QQ 发送超大正文。
- 搜索单次内部最多 Tavily/Bing 两个固定服务请求，并沿用其超时且受工具总期限约束。模型 HTTP 次数不混入搜索请求数；不宣称所有网络操作共 8 次。

明确命令或定时任务的视觉预处理、关系短评、正式日报仍有各自既有预算；它们在1.4.38已接入独立预算。通过本轮聊天工具调用的摘要草稿则必须叠加本聊天4轮/4工具/90秒/8HTTP上限，不能另开预算，至少保留一轮最终回答。真实质量与缓存收益仍需另外实测。

`1.4.45-agent-materials` 是附件/草稿联动开发候选，默认不开放。配置页增加“附件工具群”和“草稿工具群”，对应 `.env_agent_material_groups` / `QQBOT_AGENT_MATERIAL_GROUPS` 与 `.env_agent_draft_groups` / `QQBOT_AGENT_DRAFT_GROUPS`；也必须满足“有限工具灰度群”、原群准入及对应业务白名单。私聊和自动插话不新增开放，JM独立白名单不合并。能力页的基础协议验证仍仅覆盖原五工具，不重置旧探测额度，也不冒充新业务已真实验收。

任务元数据会保存在受限目录，草稿正文不写入任务文件、报告或画像；仅在同一进程短时可读，重启不恢复正文或重提中断工作。读取和每次模型调用都会复核隐私与白名单，撤回后旧草稿不可继续读取。当前阶段进度与真实开放情况见 [Agent计划](AGENT-PLAN.md)，模块定点通过不等于已部署。

首版草稿仍属于当前聊天轮次；新发言替换旧轮时，旧草稿也会中止，不是独立无限后台工作。控制台读取状态不会重提任务。工具结果的`sent:false`指生成服务没有正式发布报告，不能据此判断聊天投递；在当前聊天展示草稿仍走既有普通回复与发送账本。

搜索授权采取保守规则：例如“搜索 Debian，回忆我的项目代号”只允许查询 Debian；“不用搜索，回忆项目代号”完全不联网。复杂、后置或含否定词的搜索要求可能不开放工具，用户可拆成独立的明确搜索请求；不声称规则能够完整理解所有自然语言授权。

## 数据与失败

模型仅能选择公开工具名及有限参数，不能指定其他群、任意用户、文件路径、命令或URL；成员总结中的QQ只允许本人或本轮明确@的对象。每次执行及模型续接前复查权限和隐私代次。原话标为历史陈述，自述/管理员备注区分来源，不成为系统指令或“已验证事实”。

检索结果仍会交给当前配置的主/备模型；本地遗忘不能撤回已经交给供应商的请求。失败不会伪造结果，未知工具不执行，空结果不扩大查找范围。无原生工具接口只兼容明确公开搜索，不伪称支持原生记忆工具；Gemini 仍没有原生工具声明。

备用使用自己的真实模型身份。已读记忆可作为本轮资料交给备用，主模型的隐藏推理、签名、加密续接字段和状态工具中的旧模型身份不会跨插槽携带。

## 协议与诊断

`1.4.41-native-tool-proof` 的能力页提供管理员「验证工具」动作，提交到已有`agent_tools`后台任务。只能验证当前群聊主备配置，不接受自选URL、密钥、模型或伪造成功参数；每配置身份24小时内最多一次、每槽位最多工具请求及续接各一次、总计最多4个模型HTTP请求，不自动重试、不读聊天、不发QQ。失败或保存预算失败不记通过，结果只保存固定状态、时间与实际报告的用量，未报告用量显示未知。

QA与真实验证使用不同身份；页面只把匹配当前配置且未过期的真实证据标为已验证，两槽不能以一槽通过冒充整项通过。证明属于管理员上线诊断，不作为普通聊天的权限或每日停用门槛，过期不会自动付费探测。管理员提交结果未知时只能刷新查询；重新认证不会自动重发写入或付费请求。

执行器冻结每个插槽的模型配置以完成同提供方回合。Responses 保留原生推理/函数调用次序并使用 `call_id`；Anthropic 保留完整签名块并将并行结果合并为紧随调用的用户消息。签名不在本地验证；不兼容字段、原生托管工具类型或过大的续接状态会失败并按原路由降级。

原生续接的适配层上限是 256 项/1 MiB，但实际聊天请求还受更严格的 24000 字符总限制。它只在内存中的同插槽请求流转，不写聊天历史、前端或日志。普通正文仍走原输出清洗，`reasoning_content` 从不作为最终回复。

Linux “诊断”的消息阶段显示工具名称、完成/无结果/拒绝/不可用、回合和额度计数。请求额度明确标为非实际用量，不展示查询词、结果正文或私有推理。

协议依据：[OpenAI 推理续接](https://developers.openai.com/api/docs/guides/reasoning#keeping-reasoning-items-in-context)、[无服务端存储的推理续接](https://developers.openai.com/api/docs/guides/reasoning#preserve-reasoning-without-stored-responses)、[Anthropic 保留思考块](https://platform.claude.com/docs/en/build-with-claude/thinking#preserving-thinking-blocks)、[工具结果顺序](https://platform.claude.com/docs/en/agents-and-tools/tool-use/handle-tool-calls)。兼容端点不一定完整支持官方字段，不能以模拟测试替代其实际连接验收。
