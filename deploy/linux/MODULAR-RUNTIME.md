# QQFriend Linux 模块边界与目标实现

目标规划更新：2026-09-23。总顺序和阶段状态见 [智能化与模块化总路线](ROADMAP.md)。本文先保留已交付的维护约定，再列出尚未实现的目标、代码入口、任务和验收。

历史维护基线：`1.4.7-modular-runtime`。下述历史整理以职责和重复流程为边界，不更换前端框架、不引入数据库，也不改变聊天模型路由、关系评分和用户白名单。新目标以 `1.4.12-model-refresh` 源码为核对基线，Windows 安装继续冻结。

| 位置 | 职责 | 不负责 |

## 后台任务

- 浏览器耗时操作先获得任务编号，再查询进度。旧 `/admin/memes`、`/admin/stickers`、`/admin/diagnose/replay` 接口不删除，现有调用方仍可使用。
- 日报沿用自己的 `summaries/jobs.json`；其他管理任务元数据位于私有数据目录 `.qqfriend/tasks/admin.json`。任务输入和结果正文不落任务账本。
- 同一类管理任务互斥，最多两个并行；日报仍按群和日期互斥并限制两个并行。模块自身的白名单、业务锁和用量限制不变。
- 默认五分钟标记等待过久。AbortSignal 是中止请求，不等于工作已经停止；底层操作未结束时继续占用任务范围。没有自动重试、自动续跑或假完成。
- 重启后未完成任务标记中断，管理员需查看对应模块状态。日报发送是否完成以发送账本为准，不能清空账本后重试。
- 完成结果在内存中最多保留十分钟、最多二十份。已持久化的词库、表情与回放可以刷新读取；未保存的查证结果过期后需要重新查证，不能宣称永久保存。

## 维护与验证

新增页面使用 ES 模块并显式导入依赖，同时登记 `web-console.mjs` 的静态资源白名单。不要把共享状态命名成业务函数常用的局部参数名；页面状态采用 `uiState`。

新增耗时管理动作要同时声明允许的模块/动作与输入字段，保留业务操作自身的权限和幂等约束。不要把业务失败包装成任务成功。结果返回前移除原始接口响应、凭据和无关的完整目录快照。

存档测试必须覆盖保存失败、写入期间新修改、退出同步保存与旧异步快照竞争。公共 JSON 工具不提供跨进程锁或多文件事务，日报仍使用自身写锁，其他模块不要假定它能替代业务锁。

发布门禁为 `npm ci`、`npm run lint`、`npm test`、`npm run replay:check` 与 `npm run release:check`。前端 JS 已纳入 ESLint，测试会验证 ES 模块链接和每个导入资源的可访问性；还应使用浏览器检查实际页面操作、长任务刷新恢复及手机宽度。测试数量通过不代表真实模型的答案质量已经验证。

## 目标实现说明

本节区分已完成的 P0、实施中的 P1 与尚未实施的 P2-P5，不表示所有拟议接口已上线。文件路径是已核对的现有入口，不要求逐项新增同名模块或一次性移动文件。实施前重新核对调用方、线上配置和最新工作区；只改当前批次。

### A. 目标模块边界

| 模块 | 现有入口 | 目标职责 | 禁止越界 |
| --- | --- | --- | --- |
| 接入与发送 | `bridge/onebot-link.mjs`、`bridge/napcat.mjs` | 标准化事件、连接生命周期、确认外发结果 | 组织提示词、推测模型意图 |
| 权限与能力 | `bridge/commands/permissions.mjs`、`bridge/commands/manifest.mjs`、`bridge/capabilities/catalog.mjs` | 权限判断、能力状态和命令声明 | 自动开放管理员动作给模型 |
| 对话调度 | `bridge/reply.mjs`、`reply-group.mjs`、`reply-private.mjs`、`reply-ai.mjs` | 分流、对话生命周期、等待与执行协调 | 重复维护画像、模型协议和存储 |
| 上下文与记忆 | `bridge/context/`、`context-retriever.mjs`、`memory-profile/` | 选择相关证据、管理记忆、预算与失效 | 绕过范围读取其他群/私聊 |
| 提示词 | `bridge/system-prompts/`、`bridge/persona-style.mjs` | 确定性组装规则、任务模板和动态资料 | 自行读取存储、写状态、鉴权 |
| 模型与工具 | `bridge/model-router.mjs`、`model-mimo.mjs`、`model-ds.mjs`、`api-providers/` | 协议适配、预算、工具执行与受控降级 | 自行决定群权限或收件人 |
| 业务能力 | `bridge/group-summary/`、`features/conversation-summary/`、`features/stickers/`、`jm/` | 各自业务规则、事实校验和任务幂等 | 各写一套模型运输、通用鉴权 |
| 观测与管理 | `bridge/diagnostics/`、`api-providers/usage-metrics.mjs`、`admin-api/`、`Web/pages/` | 追踪、用量、受保护的查询和编辑 | 默认落完整聊天、提示词或私有推理 |

依赖方向是“管理/消息入口 -> 业务协调 -> 能力与基础设施”。业务模块通过明确入口协作，调度层只决定调用顺序，不吞并各模块的状态机。共享原子写入工具不能代替业务锁或跨文件事务。

### B. 最小交互契约

以下是拟议的数据含义，不是已导出的 API。优先给现有接口加适配与明确字段，不引入全局总线或新的通用框架。

| 契约 | 最少信息 | 约束 |
| --- | --- | --- |
| 请求范围 | 消息 ID、真实发送人、群/私聊范围、引用/@对象、权限、隐私代次 | 由后端生成，模型不得更改范围 |
| 对话快照 | 对话编号、修订号、当前问题、参与者、来源消息、待确认事项 | 昵称不代替身份；旧修订结果不能覆盖已纠正的新状态 |
| 能力快照 | 功能 ID、支持范围、启用/许可/健康状态、版本与观察时间 | 未知不等于正常；受权过滤，不返回密钥和路径 |
| 记忆条目 | 类型、来源 ID、所属范围、时间、状态、到期/替代关系、必要可信度 | 明确偏好优先；无来源的旧推测不能变成事实 |
| 模型结果 | `reply` / `silence` / `needs_input` / `error`、正文、原因码、实际模型和用量 | 工具协议及中间结果内部处理，不把任意文本当动作 |
| 发送结果 | `confirmed` / `failed` / `unknown`、已确认分段与消息 ID | `unknown` 不自动重发；生成成功不等于发送成功 |

长任务继续使用现有任务状态，不与模型结果枚举合成巨型状态机。任务执行成功、内容生成成功和消息送达成功分别表达。
