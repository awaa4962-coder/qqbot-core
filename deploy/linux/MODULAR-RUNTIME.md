# Linux 模块维护说明

适用版本：`1.4.7-modular-runtime`。Windows 安装保持冻结。此次整理以职责和重复流程为边界，不更换前端框架、不引入数据库，也不改变聊天模型路由、关系评分和用户白名单。

## 当前边界

| 位置 | 职责 | 不负责 |
| --- | --- | --- |
| `Web/app.js` | 导航、页面事件与初始化 | 各功能表单和列表的实现 |
| `Web/pages/` | API、梗库、表情、配置等页面渲染 | 直接写服务器文件 |
| `Web/ui/` | 明确的共享状态、操作反馈、轮询和宿主适配 | 推测任务已取消、擅自重新提交 |
| `bridge/tasks/runner.mjs` | 任务生命周期、并发、进度和重启中断状态 | 业务权限、QQ 发送重试、下载调度规则 |
| `bridge/admin-api/task-manager.mjs` | 固定操作白名单和公开结果裁剪 | 客户端指定文件路径、执行任意命令 |
| `bridge/jm/` | 命令、运行检查、压缩、临时目录和共用传输流程 | 合并群白名单与私聊白名单 |
| `bridge/persistence/json-file.mjs` | 原子写入、保存排队和退出 flush | 画像算法、数据迁移、跨文件事务 |
| `bridge/memory-profile/` | 存储、事件更新、查询和展示 | 改变已有画像规则与关系分数 |
| `group-summary/generation-plans.mjs` | 结构化与旧格式展示策略 | 重复实现主备模型执行 |

`jm-provider.mjs` 和 `memory-profile.mjs` 是兼容入口，原导出仍可用。旧 LLM 客户端保留调用形状，共用 `api-providers/transport.mjs`；一次旧请求仍只尝试一次。正式聊天任务继续使用已有任务路由，不改主备分配。

## 后台任务

- 浏览器耗时操作先获得任务编号，再查询进度。旧 `/admin/memes`、`/admin/stickers`、`/admin/diagnose/replay` 接口不删除，现有调用方仍可使用。
- 日报沿用自己的 `summaries/jobs.json`；其他管理任务元数据位于私有数据目录 `.qqfriend/tasks/admin.json`。任务输入和结果正文不落任务账本。
- 同一类管理任务互斥，最多两个并行；日报仍按群和日期互斥并限制两个并行。模块自身的白名单、业务锁和用量限制不变。
- 默认五分钟标记等待过久。AbortSignal 是中止请求，不等于工作已经停止；底层操作未结束时继续占用任务范围。没有自动重试、自动续跑或假完成。
- 重启后未完成任务标记中断，管理员需查看对应模块状态。日报发送是否完成以发送账本为准，不能清空账本后重试。
- 完成结果在内存中最多保留十分钟、最多二十份。已持久化的词库、表情与回放可以刷新读取；未保存的查证结果过期后需要重新查证，不能宣称永久保存。

## 维护与验证

新增页面使用 ES 模块并显式导入依赖，同时登记 `web-console.mjs` 的静态资源白名单。不要把共享状态命名成业务函数常用的局部参数名；页面状态采用 `uiState`。

新增耗时管理动作要同时声明允许的模块/动作与输入字段，保留业务操作自身的权限和幂等约束。不要把业务失败包装成任务成功。结果返回前移除原始接口响应、凭据和无关的完整目录快照。

存档测试必须覆盖保存失败、写入期间新修改、退出同步保存与旧异步快照竞争。公共 JSON 工具不提供跨进程锁或多文件事务，日报仍使用自身写锁，其他模块不要假定它能替代业务锁。

发布门禁为 `npm ci`、`npm run lint`、`npm test`、`npm run replay:check` 与 `npm run release:check`。前端 JS 已纳入 ESLint，测试会验证 ES 模块链接和每个导入资源的可访问性；还应使用浏览器检查实际页面操作、长任务刷新恢复及手机宽度。测试数量通过不代表真实模型的答案质量已经验证。
