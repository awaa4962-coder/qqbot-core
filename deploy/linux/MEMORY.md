# Linux 明确记忆

当前源码 `1.4.26-memory-lifecycle`，实际上线以实施记录为准。条目继续保存在既有记忆文件中；没有新增数据库，也没有每轮提取模型。功能与数据边界见下文，批次验收不代表最终2.0.0已完成。

## 类型与来源

新条目的 `recordType` 为 `unclassified`（未分类）、`fact`（事实说明）、`event`（历史事件）、`todo`（待办事项）或 `current_state`（当前状态）。旧条目保持未分类，不根据标题、正文或来源猜类型；前端可由管理员显式补分类。`kind` 区分用户自述 `user_statement` 与管理员备注 `operator_note`；`source.kind` 独立记录 `user_command` 或 `operator`。记录类型、作者归属和写入来源不可混用，管理员编辑仍是管理员备注。

事件的 `eventAt` 表示明确的发生时间，可以为空；不得用来源时间 `source.at` 代替，也不得记录未来时间。未来安排应作为待办记录；命令不猜日期，明确发生时间可在控制台填写。

## 命令

| 命令 | 行为 |
| --- | --- |
| `@夜星 记事 <事实\|事件\|待办\|状态> <标题> = <内容>` | 按指定类型新增本人记忆；事件日期默认未知 |
| `@夜星 事项状态 <id> <待办\|进行中\|已完成\|已取消\|当前有效\|已结束>` | 明确变更该条目的状态 |
| `@夜星 记住 <标题> = <内容>` | 兼容旧命令，新增条目不推断类型 |
| `@夜星 纠正记忆 <id> = <内容>` | 在原 ID 上纠正正文、保留原到期时间，不按标题自动合并 |
| `@夜星 删除记忆 <id>` | 删除指定条目，不删除原聊天记录 |

待办状态映射为 `pending`、`in_progress`、`done`、`cancelled`；当前状态映射为 `current`、`ended`。只有明确命令或控制台状态操作能转换状态。转换不改正文、不续 TTL；过期只表示当前未知，不能推断为相反状态。“已完成”仅记录操作者声明，不证明机器人或外部系统实际执行。

群聊沿用 @ 门禁；私聊仍需普通私聊白名单，管理员只能管理自己。私聊命令只授权该次明确操作，不开启自动长期保存。群聊命令回复对本群可见。各群和私聊相互隔离，不能用参数指定他人身份。

每人每范围最多32条、全局2048条；标题32字、正文300字。新建默认30天，控制台可明确设置1–90天；闲聊和状态更新不续期。普通纠正保留期限，过期条目必须明确续期或删除后重新记住，不能靠纠正偷偷恢复有效。

## 控制台

Linux 控制台“记忆”页须先选择群/私聊和 QQ 号，不自动加载所有用户。管理员备注仍以 `operator_note` 保存，来源记为 `operator`，绝不伪装成用户自述或用户命令。前端可以为旧条目补分类、填写事件日期，并独立提交状态；状态提交不覆盖正文或重置期限。

旧快照修改返回冲突并保留草稿。网络结果未知时先刷新确认，不连点重交。损坏或不可写的记忆文件应报错，不重置文件制造成功。

## 召回与边界

- 聊天与只读 recall 接收结构化记忆字段；提示词版本沿用 `chat-v11`。事项状态和后端核验的记录有效性分开：事项结束不等于记录过期，记录未过期也不代表外部服务刚被实时检查。引用原消息若已被纠正、删除或对应条目过期则拒绝，不以附近历史代替。新记忆命令不混入普通历史。
- 实际入选的线程回合传递完整条目依赖，不因诊断来源显示上限而丢失。旧线程没有完整依赖版本标记时保守弃用，包括旧版留下的空依赖数组。纠正或删除后，依赖它的转述回合也退出；剔除部分回合时不再沿用旧整体话题。完整来源组和工具续问预算见 [上下文预算](CONTEXT.md)。
- 记忆变更使在途聊天、工具、图片描述及后台旧画像生成结果失效。用户本轮明确纠正优先，但普通聊天不会因此自动写入长期条目；要持久化仍使用明确命令或控制台。遗忘沿用既有持久化截止线，历史备份须另行管理。
- 来源只说明记录如何写入，不证明内容属实。事件时间与来源时间各自表达不同信息；缺失的类型或日期保持未知。
- 偏好与模型推测继续独立，不把它们混成长期记录。关系评分、JM、模型主备与思考档位、权限和私聊自动长期保存策略不变。
- 原有范围隔离、显式保存边界与遗忘规则继续适用。普通聊天不会因此自动提取或保存记忆。

显式来源失效会沿当前存档中的replyToMessageId/turnId关联传播，不根据语义相似度删除别人的独立发言。过期条目删除前保留原有retractions格式，容量上限8192，达到上限时拒绝继续修改，不静默丢弃否定记录；既有保留条件仍适用，不承诺找回不存在于本地存档的完整关联图。提及对象的话题线索和新启动的后台画像均过滤失效来源。

“忘记我”先增加代次，随后处理原有隐私截止线、明确条目、画像、用户/群聊天、用量及发送身份。成功前通过同一保存器同步确认用户/群聊天和画像，fsync失败会返回未确认提示，清理后的内存不回滚成旧内容，可在存储修复后重试。文件之间不是跨文件事务；部分成功时不宣称全部完成。历史备份和已交给模型/QQ的内容不能借此撤回。普通聊天防抖保存频率不变。

关系评分不使用明确notes集合。记忆命令作为一条真实收到的群消息仍遵守原计数规则，但保存/修改条目不会重复计互动或因fact/todo等类型加分。群内关系只用该群资料，私聊本人查询保留既有个人汇总范围，本轮没有重新定义关系算法或范围。

## 回滚

旧版 `1.4.23` 可以读取新增字段，但旧编辑器写入可能丢失分类。若已有 typed 新数据，不得直接启用旧写路径：必须先提供兼容补丁，或保持 Bridge 停用新写路径等待修复。绝不以旧备份覆盖新数据。回滚时保留新数据，并明确记录停写状态。

测试、模型样例的局限和实际部署证据见 [实施记录](MODULAR-RUNTIME.md)。仍需整体验证跨入口纠正、完整上下文预算与回答质量。
