# Linux 明确记忆

`1.4.20-memory-evidence` 在既有记忆文件中增加有来源的条目，没有另建聊天库或向量库。阶段性功能，不代表 2.0.0 已完成。

## 群成员命令

| 命令 | 行为 |
| --- | --- |
| `@夜星 我的记忆` | 查看本人在本群的条目及编号 |
| `@夜星 记忆帮助` | 查看格式与范围 |
| `@夜星 记住 项目系统 = 项目使用 Debian 容器` | 明确保存一条自述，不代表已核验事实 |
| `@夜星 纠正记忆 <id> = 项目现在改用 Fedora` | 替换当前值、增加修订，不把旧正文复制到版本库 |
| `@夜星 删除记忆 <id>` | 删除指定条目，不删除原群聊天记录 |

私聊可省略 @，需普通私聊白名单，管理员沿用命令豁免但只能管理自己。私聊“记住”仅授权这一条，不开启自动长期保存私聊；群内命令回复对本群可见，不要在群里保存秘密。各群与私聊分开，不能用参数指定他人的身份。

每人每范围最多 32 条，标题最多 32 字、正文 300 字。命令默认 30 天；控制台可设 1–90 天。闲聊不会续期，过期立即不进模型，维护任务随后清理；更改条目会重新计算明确指定的期限。

## 控制台

Linux 浏览器控制台的“记忆”页必须先选择群/私聊和 QQ 号；不自动加载所有用户。可以新建管理员备注、编辑、删除，并查看来源、修订和期限。保存后标记为管理员备注，不声称用户亲口说过；明确称呼/风格仍由原设置系统维护。

旧快照修改返回冲突，草稿保留、不得自动覆盖。网络结果未知时先刷新确认，不连点重交。损坏或不可写的记忆文件会报错，不重置文件制造成功。

## 上下文与边界

- 模型按问题相关性选用最多四条本范围记忆；用户本轮纠正、主动称呼和风格高于旧资料。资料不具备系统指令权限，不代表操作已经执行。
- 入选条目会随上下文交给当前配置的模型服务参与回答。本地遗忘不能撤回供应商已接收的请求；请勿保存凭据或不适合交给模型的内容。聊天生成本身没有长期记忆写入工具，只有命令/控制台的实际保存结果才能表示成功。
- 管理员备注、自述和原话话题线索分开标识。话题线索只来自最近七天本群有编号的原话，复读去重，不推断喜恶或经历。
- 旧规则画像保留给已有关系计算和兼容查询，分数逻辑未改；不再作为普通聊天或被提及者的事实画像注入。不会给无来源旧画像补造证据。
- 纠正条目的原来源不参与普通历史回填；相关纠正前的旧助手轮次不作为当前结论继续使用。明确引用原话仍表示历史发言，并不证明目前仍成立。
- 确认发送的聊天轮次记录所用记忆编号与修订；之后纠正或删除会使旧依赖失效。旧版本没有依赖标记的线程采取保守失效，不把未知旧结论当作新事实。旧来源否定标记不存正文，全局最多 8192 条，至少保留一天且原话仍在滚动历史时不移除；满容量拒绝覆盖，不丢弃仍有效的纠正记录。
- 记忆命令在等待、写入前及分段发送前复核隐私代次与权限。遗忘后尚未发送的段停止，已经交给 QQ 的段无法撤回；这不是所有业务命令的持久化任务队列。
- `忘记我` 清理各范围条目，并沿用既有持久化遗忘截止线。旧编辑快照及正在运行的旧回复失效；历史备份仍需管理员单独处置。
- 诊断只展示来源编号、修订和原因，不记录条目正文或推理。API 配置、JM 的 FS/白名单/延迟清理、关系评分及导出预留态不变。

后续仍需完成更广泛的来源化事件、受限模型查询工具、图片语境和缓存对照；没有新增每轮画像/意图/反思模型请求。
