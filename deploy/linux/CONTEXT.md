# Linux 上下文预算

本批源码版本 `1.4.25-context-groups`，上线状态以 MODULAR-RUNTIME.md 的实际记录为准。Windows 安装不更新。

## 取材和完整性

历史原话按作者、消息ID、时间、引用关系和正文组成独立证据。真正存在的引用关系合并为预算组；turnId不冒充引用关系。长链只选择有界邻域，未提供父消息明确说明，不宣称取回全部历史。

初选保留当前输入预算，按来源组优先级取舍。带来源的正文不再直接截掉中间内容；组无法满足消息数、字符、128条来源或32个记忆依赖限制时整组舍弃。明确记忆的纠正和删除规则不变。

既有持久化仍保留群消息前500字符、个人历史前300字符。新增textChars/textTruncated描述脱敏后原文与所存片段；不恢复以前丢失的文字。旧数据字段缺失或相互矛盾时为完整性未知，短句也不自动推断完整。当前展示摘录的截短标记与存档完整性分开。

## 私聊附件

仍须通过普通AI私聊白名单。仅原有文本格式，最多前三份、每份10000字节和8秒获取时限，URL/DNS每跳校验不变。不新增PDF/Word解析，不回填第四个附件来掩盖前三个读取失败。

当前问题与附件正文分开；private-file初选上限14000字符，单条11000字符。附件与当前问题不做隐式头尾剪贴；当前问题本身超出总预算时拒绝，不声称已经作答。模型收到实际提供/未读取/未提供份数，用户的遗漏说明置于回复开头，部分发送也不会只留下无范围说明的答案。仅接受完整HTTP 200且无Content-Range的文本响应，206片段拒绝。隐私处理后的可读文本不等同原始二进制文件逐字节完整；不支持、空白或太大时明确未读。短期会话只存问题、文件数量及实际确认回复摘要，不把完整附件写进会话记录。

## 工具续问

发送前按24k字符预算重查文本、工具定义、工具结果、原生协议续问、额外控制字段和动态自身信息，协议转换和脱敏后的JSON正文再次测量。字符预算不等于供应商精确token计数，图片有独立字节/像素预算，仅后端本轮准备的图片字节在对应协议的用户图片槽位豁免。

仅已登记的可舍弃旧组允许移除。引用、明确记忆、偏好、附件、当前问题和原生工具调用/结果不从中间裁开；保护内容仍超预算则停止该次请求，走既有有界主备处理，不宣称成功。请求外的WeakMap只保存组元数据，不写进模型JSON或持久化。回合失效依赖保守保留初选与工具来源的并集，不冒充精确的最终答案归因；某旧组后续移除，也可能已被前轮模型用过。保守依赖可能导致额外失效，不能为了减少失效删除已消费的保护。没有付费压缩器或逐轮额外总结，因此不产生压缩调用和费用。

## 诊断与回滚

控制台显示初选、续问移除和发送前选择。来源显示最多24条，多余仅是页面省略，实际所选来源保留；不显示文件名、URL、正文或私有推理。发送前选择不代表发送或送达成功，送达以原发送账本为准。

群/用户历史仍为原JSON结构，两个新字段是可选元数据。可代码回滚至1.4.24，新字段由旧代码透传或忽略；旧版继续追加的记录缺少字段，恢复新版后会标未知。1.4.24已经支持明确记忆分类，不得误用1.4.23及更早写器覆盖typed记忆。回滚只切源码与镜像，不用旧备份覆盖新数据。
