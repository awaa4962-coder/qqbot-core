# Linux API 用量

本说明对应 `1.4.23-usage-dimensions` 用量模块。管理员可在现有控制台 API 页的用量区只读查看记录；该区域不修改模型配置或发起模型请求，原有 API 编辑器保留。

## 记录与筛选

用量以每次实际发出的物理 HTTP 尝试为单位，记录当时配置的模型、任务、primary/fallback 插槽、提示词版本与指纹，以及 configured/effective reasoning mode。可按 1、7、30 天和提供方、模型、任务、插槽、提示词、实际模式筛选。缓存命中率/权重只按已测得的 input token 计算，不把估算值说成供应商账单。

OpenAI Chat、Responses、Anthropic、Gemini 等响应格式归一化为 input、output、reasoning、total，并分别保留供应商是否报告该维度的标志。缺少 usage 不会补成零。页面区分完整读取、部分读取、未报告、旧格式和未知；部分结果不能解释为完整总量。旧记录缺少模型、版本或模式时显示 unknown；旧格式中的零不是已确认的真实零，正数仍保留为有效记录。未版本化任务不回填猜测的版本。页面不展示价格、费用或节省金额。

## 隐私与遗忘

本人统计用 HMAC 关联用户，查询窗口最多30天。日文件按30天滚动清理，边界日可能多留不足一天；清理在后续写入时执行，停机或长期无写入不承诺自动物理删除。记录不得包含请求/回复正文、私有 reasoning、API key 或原始用户 ID。原有成员缓存命中命令继续可用，管理接口不返回身份散列。

用户遗忘操作与普通 usage 共用每日 `usage-YYYY-MM-DD.jsonl` 文件。普通 usage 写入最多占 16 MiB，并额外预留 1 MiB 给 reset 记录；读取上限为 17 MiB。reset 写入需经 fsync 确认后才算成功。若对应容量耗尽或写入/fsync 失败，forget 必须返回失败并向调用方传播，不能报告遗忘成功。

## 故障处理与回滚

用量读取或归一化失败时应显示错误或部分/未知状态，不应静默显示为零，也不应阻断聊天请求。若管理员页面不可用，先按管理端只读诊断流程检查；不要通过改写用量文件、清除 reset 记录或发起模型调用来“修复”统计。

旧版可读取原 `usage-YYYY-MM-DD.jsonl` 格式中的 reset 记录，因此回滚不要求保留新版模块补丁。回滚会失去新版的用量统计精度和容量保护；不得回灌旧状态，也不得删除或重置文件来绕过 reset。新版本中 forget 的写入/fsync 失败必须传播为明确失败。

本批没有真实付费模型调用或QQ测试发送；具体候选、测试与上线证据见 [实施记录](MODULAR-RUNTIME.md)。查询次数不是成功回答数，读取完整也不等于所有调用都报告了用量，不能从命中率推算节费或回答质量。
