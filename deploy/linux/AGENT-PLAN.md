## 当前目标

完成原 P0-P5 的 43 项验收，同时把夜星扩展为能够按需查资料、读本轮材料、计算并调用少量既有业务的有限 Agent。复用现有 `chat-tools`、模型路由、任务执行器、权限、上下文、输出清洗及发送账本，不再建第二个机器人框架。仅推进 Linux，Windows 安装冻结；JM 和既有白黑名单继续保留。全部约定范围通过后才正式发布 `2.0.0`。

原计划当前完整验收 **35/43 = 81.4%**；剩余 P3-06 与 P5-01 至 P5-07。新增 Agent 任务独立编号，共 12 项，当前代码/隔离工程验收 **3/12 = 25.0%**；实际模型兼容、生产灰度、附件和写操作尚未验收。不得把新增功能算作原任务的完成，也不得删除旧任务提高百分比。每轮报告两份清单、本轮净增及尚未验收的原因。

2026-09-30，用户删除旧持续目标后，已按本文重新建立自动持续目标，状态为 `active`。从当前已验收进度继续，不重做第一批；删除旧目标不代表旧项目任务已经完成。每轮按原清单与新增 Agent 清单分别报告证据和百分比。

## 不变边界

- 主备共享 4 个模型轮次、4 次工具调用、90 秒、8 次模型 HTTP 尝试；工具结果沿用单份 2000 字符、总量 6000 字符上限。没有额外意图判断、规划或反思模型。
- 普通自动插话不开放工具；明确命令继续走确定性解析。首期新增能力默认关闭，只在明确配置的一个群、主动 @ 对话灰度；私聊首期不新增开放。
- 记忆只能读取当前用户当前授权会话。搜索只能使用当前用户明确授权的公开问题；不得拿记忆、附件、引用或网页里的指令拼外发查询。
- 网页、附件和工具结果是不可信资料，不是系统指令。网页引用由后端绑定本轮授权 URL，不接受任意 URL、本机路径或跨轮引用。
- 不开放 shell、任意文件访问、源码/密钥/模型配置编辑、服务重启、插件安装、管理员群操作或通用消息发送工具。
- 保留主备模型、思考档位、DeepSeek 能力、认证 helper、逐跳 DNS/SSRF 防护、隐私代次、推理隔离、发送账本和关系评分；关系导出继续预留。
- 写操作之前先完成存档损坏保护、退出保存结果及真实发送结果复核；未知回执不自动重发，回滚只换代码和镜像，不覆盖上线后的新状态。

## 第二阶段：本轮附件与业务草稿

- [ ] A2-01 本轮附件引用：后端生成 `attachment_ref`，绑定消息/用户/会话/隐私代次、类型、大小、有效期和覆盖范围；模型不能提交路径。
- [ ] A2-02 按需读取：复用附件读取服务，明确已读部分与未读部分；支持查询或区段，拒绝扩大范围；不把整个文件默认塞进提示词。
- [ ] A2-03 既有业务窄接口：日报和多人聊天总结先生成草稿/结果，不直接发布、不自动保存私人画像；保留各业务自己的权限和幂等检查，JM 不移除。
- [ ] A2-04 长任务整合：复用现有任务状态、取消与结果账本，嵌套模型调用纳入同一任务总预算；前端和聊天反馈真实，不擅自重提或重复发送。

## 第三阶段：少量可确认写操作

- [ ] A3-01 自己的偏好和明确记忆：只操作请求者本人，先给具体变更草稿；范围、参数和隐私规则由后端决定。
- [ ] A3-02 一次性确认：绑定发起人、会话、动作、具体参数、到期时间与幂等键；跨人、跨群、篡改、重复及过期确认不得执行。
- [ ] A3-03 提醒恢复：建立有限提醒服务及持久化调度/重启恢复，不能把当前后台任务队列冒充提醒系统；不提供通用定时外发。
- [ ] A3-04 写入与发布门禁：持久化失败不报成功；撤回/遗忘/取消生效，确认及外发结果可追踪；完整回归、受限备份、灰度观察和回滚演练后才发布。

## 多子代理与分轮审计

此处的子代理是开发协作，不是给生产 Bot 引入多个 Agent。

1. 主代理先固定本轮接口和验收样例，将互不相交的文件分给 2 至 4 个实现子代理；主代理持有公共接口、权限、预算和集成。每个子代理只改自己的文件，保留未提交改动，完成后列文件及针对性测试。
2. 第一轮审计：安排未编写该模块的子代理检查权限、注入、SSRF、预算、取消、错误状态和接口兼容；只读审计，按严重程度提供可复现证据。实现者不能自行关闭问题。
3. 第二轮审计：修正第一轮缺陷后，另一子代理交叉检查调用方、前端状态、降级、持久化及模块冗余；必要时加入对抗测试，不反复全文阅读和无限派单。
4. 主代理复核所有发现及 diff，集中运行一次完整门禁。任何密钥、私有推理、越权、错误收件人、假成功、重复外发或无法恢复的状态均阻断发布，不用平均评分抵消。
5. 每轮审计记录发现、修改、证据、未解决项和复核人。离线通过、真实模型往返、Linux 候选、灰度观察、生产部署分开记录；未完成的检查不得勾选。

子代理不得自行调用付费模型、连接真实 QQ 发送测试、改真实配置、提交/推送或部署；由主代理统一执行。不会同时运行两个实际发消息的 Bot。

## 验收与发布

开发中先跑针对性回归；整合后 `npm ci`、lint 0 错误/0 警告、全部测试、回放与 `release:check`。原生工具兼容探测用合成数据，对每个实际主备槽位最多一次工具请求和一次结果续接，不自动付费重试；记录配置指纹、工具名、次数及用量，不保存私有推理。

源代码安全备份、明确暂存及隐私扫描后同步既有 GitHub Linux 分支；新依赖必须进入生产镜像，不能沿用没有安装依赖的 overlay。隔离 Linux 候选不接真实 QQ；生产切换先保存访问受限的状态备份，重新拉起并核验版本、健康、就绪、NapCat 和 JM。首个灰度群在部署时明确选定，操作记录保留在受限位置；观察满足原 P5 门禁后再扩大。
